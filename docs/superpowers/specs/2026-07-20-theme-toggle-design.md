# Theme Toggle (Light / Dark) — Design Spec

**Date:** 2026-07-20
**Status:** Draft → pending user review
**Scope:** Add a light theme + a navbar theme toggle to the existing dark-only portfolio.

---

## 1. Goals

- Give the site a coherent **light mode** in addition to the existing dark mode, controlled by a single toggle.
- Reuse the existing centralized CSS variables — do **not** duplicate the palette in components.
- Animate the theme change using the **circle-spread** transition from Lightswind’s `ToggleTheme`.
- Persist the user’s choice across reloads.

Non-goals:

- No system-preference auto-detection (we can add it later if requested — kept out to avoid scope creep and a second source of truth).
- No “auto / light / dark” tri-state — a binary toggle is enough.

## 3. Component

### `ToggleTheme` (Lightswind)

- Library: `lightswind` (added via `npx lightswind@latest add toggle-theme`).
- Import: `import { ToggleTheme } from "@/components/lightswind/toggle-theme";`
- Props used: `animationType="circle-spread"` (default), `duration={600}`.
- Renders a small icon button. Driven internally by Lightswind — manages the `dark` class on `<html>`.

### State persistence

Lightswind’s toggle writes to `localStorage` under its own key. We’ll verify the exact key during implementation; if it’s not persisted across reloads, we wrap the component:

```jsx
// On mount, read localStorage and set the class manually if needed.
useEffect(() => {
  const stored = localStorage.getItem("theme"); // or whatever key Lightswind uses
  if (stored === "light") document.documentElement.classList.remove("dark");
  if (stored === "dark") document.documentElement.classList.add("dark");
}, []);
```

If Lightswind already handles persistence, this becomes a no-op. **Confirmed during plan execution.**

### Navbar placement

Desktop:

```
[Brand] [Work] [About] [Stack] [Notes] [Contacts]      [Search ⌘K] [☾/☼] [Get in touch →]
```

Mobile (inside the slide-down menu, not the header bar — header bar already carries hamburger + brand):

```
… nav items …
[Theme toggle row] [Get in touch →]
```

The toggle sits to the **left of** `Get in touch` on desktop, to mirror the existing visual rhythm. Sized to match the Search chip height.

### Styling override

Lightswind ships its own button chrome. We wrap it in a div matching the navbar’s chip style (border, mono-label spacing) so it visually integrates. The toggle’s actual icon stays as Lightswind renders it.

```jsx
<div className="inline-flex h-[34px] w-[34px] items-center justify-center rounded-sm border border-border bg-[var(--bg-elev1)] text-[var(--fg-muted)] transition-colors hover:border-[var(--border-hi)] hover:text-fg">
  <ToggleTheme animationType="circle-spread" duration={600} />
</div>
```

(Final sizing reconciled with Lightswind’s actual rendered size during implementation.)

## 5. Risk / Notes

- **Existing `data-theme="dark"` on `<html>` (index.html)** — confirm Lightswind reads `dark` class on `<html>` rather than `data-theme`. If it expects `data-theme`, we’ll write a small bridge in `Layout.jsx` to mirror one to the other.
- **Grain overlay** uses a fixed black/white noise SVG — works in both themes (opacity 0.035).
- **Grid backdrop** uses `rgba(255,255,255,0.03)` — invisible in light theme. Acceptable; light theme doesn’t need a grid.
- **Vignette overlay** uses `rgba(8, 8, 11, 0.6)` — would look like a dark spot in light theme. Will be hidden in light mode via `html.light .vignette::before { display: none; }`.
- **Hero `grid-bg` radial gradient + floating glyphs** — same as above, hide in light theme.
- **Light glow behind portrait (rgba(255,255,255,...))** — currently white. In light theme this would disappear into the background. Acceptable; the radial gradient was already subtle.

## 6. Verification

1. `npm run build` — clean.
2. Reload on dark → toggle → see circle-spread → site switches to off-white palette.
3. Reload — selected theme persists.
4. Toggle back → smooth animation back to dark.
5. Mobile drawer — toggle present and functional.
6. No hardcoded white/black leaking anywhere.

## 7. Out of Scope

- Auto / system preference detection.
- Per-section / per-route theme overrides.
- Custom toggle UI (we use Lightswind’s component as-is).
- Removing the existing dark theme — both remain.
